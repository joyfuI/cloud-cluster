# Cloud Cluster

Cloud Cluster는 여러 클라우드 계정을 하나로 묶어서 관리할 수 있는 파일 관리자입니다.
새 파일은 서로 다른 두 계정에 저장합니다. 복제본을 비교하고 누락된 사본이나 폴더는 검사 결과에서 직접 보충할 수 있습니다.

## 빠른 시작

대상 환경은 Windows 10 x64 1809 이상과 Windows 11 x64입니다.

1. 쓰기 가능한 앱 전용 폴더에 `CloudCluster.exe`를 놓고 실행합니다.
2. **계정 관리 → 계정 추가**에서 제공업체를 선택하고 인증합니다. Google Drive는 자체 OAuth client ID가 필요합니다.
3. 새 파일을 두 곳에 저장하려면 대상 경로에 쓸 수 있는 계정을 두 개 이상 연결합니다.
4. 파일을 창에 끌어 놓거나 업로드 버튼으로 파일 또는 폴더를 선택합니다. 기존 파일을 교체해야 할 때는 계정과 경로를 보여주고 **덮어쓰기** 또는 **건너뛰기**를 묻습니다.

기존 연결을 쓰려면 **설정 → 기존 rclone config**에서 평문 config를 선택하고 재시작합니다.
**계정 관리**에서 필요한 리모트만 **사용으로 변경**합니다. 앱에서 갱신한 토큰과 연결 설정은 선택한 config 파일에 저장될 수 있습니다.
제공업체별 인증과 계정 용량은 [계정 관리](docs/user-guide.md#계정-관리)를 참고하세요.

## 주요 작업

| 작업 | 사용 방법 |
| --- | --- |
| 탐색과 선택 | 주소창, 폴더 트리, 이름 검색과 상태 필터를 사용합니다. 이름 뒤 여백이나 목록의 빈 공간을 드래그하면 여러 행을 선택할 수 있습니다. |
| 파일 관리 | 업로드·다운로드, 복사·이동, 이름 변경, 새 폴더와 삭제를 지원합니다. 파일을 더블클릭하면 기본 다운로드 폴더로 받습니다. **다운로드...**에서 위치를 고르거나 Windows 파일 탐색기에 파일을 놓을 수 있습니다. 기존 파일을 덮어쓸 때는 확인합니다. |
| 복제본 관리 | 계정별 사본을 골라 다운로드·복제·삭제하거나, 실제 바이트를 읽어 정밀 검증합니다. |
| 폴더 검사 | **현재 폴더 검사**로 현재 경로와 하위 폴더를 조회합니다. 루트에서 실행하면 전체 관리 범위를 검사합니다. |
| 문제 해결 | 결과에서 누락 폴더, 복제 부족, 검증 불가 항목을 선택해 처리합니다. 충돌과 복제 초과는 **복제본 관리**에서 확인합니다. |
| 작업 큐 | 진행률과 작업 결과를 확인합니다. 작업 행 메뉴에서 취소하거나 최신 상태로 재시도할 수 있습니다. |
| 휴지통 비우기 | 계정 관리에서 지원 계정의 휴지통 항목을 영구 삭제합니다. 개별 항목 조회와 복원은 서비스의 웹 화면에서 합니다. |

기본 단축키는 `Ctrl+C/X/V`, `F2`, `Delete`, `F5`, `Alt+←/→/↑`, `Ctrl+L`, `Ctrl+Shift+N`입니다.
작업 행에서 `Shift+F10`을 누르면 행 메뉴가 열립니다. [파일 작업과 작업 큐](docs/user-guide.md#파일-작업)의 상세 동작을 확인할 수 있습니다.

## 데이터와 알려진 한계

- 기본 데이터 폴더는 배포 exe 옆, 소스 실행 시 프로젝트 루트입니다. `--data-dir "D:\CloudClusterData"`로 변경할 수 있습니다.
- `settings.json`에는 앱 설정과 사용 리모트 이름이, `rclone.conf`에는 **암호화되지 않은 인증 정보**가 저장됩니다. 이 config는 공개하거나 공유하지 마세요. 포터블 이동과 로그 위치는 [데이터 폴더와 로그](docs/user-guide.md#데이터-폴더와-로그)를 참고하세요.
- 변경은 사용자가 시작합니다. 조회 실패는 파일 부재와 구분하고, 작업 큐는 메모리에 유지합니다. 작업 중단 후에는 현재 원격 상태를 다시 확인할 수 있습니다.
- 일괄 이동은 대상 파일의 전송·검증이 끝난 뒤 원본을 삭제합니다. 삭제 전에 대상 파일과 폴더를 다시 확인하며, 그 조회와 실제 삭제 사이에는 외부 변경이 일어날 수 있습니다. 덮어쓰기의 원자성과 삭제 후 복구 가능 여부는 제공업체에 따라 다릅니다.
- 정밀 검증 결과와 비교 가능한 해시가 부족할 때의 업로드 검증 결과는 `content_hashes.db`에 저장할 수 있습니다. 해시가 없어 크기·수정 시각을 근거로 재사용하는 경우, 같은 크기와 시각을 유지한 변경을 놓칠 수 있습니다. [정밀 검증과 캐시](docs/user-guide.md#정밀-검증과-캐시)에 재사용 조건이 있습니다.
- 실제 클라우드 OAuth·제공업체별 쓰기와 휴지통, 깨끗한 Windows 10/11 환경은 검증이 남아 있습니다. 배포 exe는 환경에 따라 Windows 런타임 설치가 필요할 수 있습니다.

## 소스 실행과 Windows 빌드

일반 Windows CPython 3.15.2와 uv를 사용합니다. DLL을 빌드하려면 Go 1.27.2와 MinGW GCC가 필요합니다.
첫 빌드는 공개 패키지와 rclone 소스를 내려받습니다.

```powershell
uv sync --locked
.\scripts\build-librclone.ps1
uv run --locked cloud-cluster
```

빌드 스크립트는 rclone v1.76.0의 고정 소스와 폴더 이름 변경 연결 코드를 사용해 `librclone.dll`을 생성합니다.
앱은 이 DLL을 직접 사용합니다. 배포본을 만들 때는 다음 명령을 실행합니다.

```powershell
uv sync --locked --all-groups
.\scripts\package.ps1
```

Nuitka 4.3.4와 Zig로 `dist\CloudCluster.exe`를 생성합니다. Nuitka의 Python 3.15 지원은 실험적입니다.
Qt 라이브러리와 한국어 번역, rclone DLL, 빌드 정보와 라이선스 고지를 exe에 포함합니다.
**도움말 → 오픈소스 라이선스**에서 소스와 라이브러리 교체 안내를 볼 수 있습니다.
공개 배포 조건은 [라이선스와 대응 소스](licenses/SOURCES.md), 테스트 절차는 [개발 지침](AGENTS.md#검증과-데이터-격리)에 있습니다.
