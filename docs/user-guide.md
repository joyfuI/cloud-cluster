[빠른 시작과 Windows 빌드](../README.md)

## 계정 관리

### 연결과 인증

첫 실행은 빈 탐색기입니다. **계정 관리 → 계정 추가**에서 리모트 이름과 제공업체를 정하고
**추가**를 누르면 rclone의 전체 설정 질문을 차례로 표시합니다. **재인증**도 같은 절차를 사용하며
기존 저장값을 기본값으로 제시합니다. 별도의 설정 입력 폼은 없고 현재 질문에만 답합니다.
창은 처음부터 같은 높이로 열리고 질문 전환에 따라 자동으로 커지지 않습니다. 긴 안내는
질문 영역을 스크롤해 확인할 수 있으며 창 크기를 직접 조절할 수도 있습니다.
제공업체 목록과 설정 질문은 내장 rclone DLL에서 조회하므로 포함된 DLL 버전에 따라 지원
목록이 달라집니다. 목록은 표시 이름을 한국어 정렬 순서로 정렬하고 새 계정의 기본 선택은
Google Drive입니다. 질문의 도움말은 한국어로 표시합니다. Qt 기본 버튼, 입력 창과
텍스트 편집 메뉴는 공식 한국어 번역을 사용합니다. Windows 기본 파일 선택 창은 OS 언어
설정을 따르며, Qt 파일 선택 창에는 같은 한국어 번역을 적용합니다.
리모트 이름은 rclone 규칙에 따라 한글 등 문자와 숫자, `_`, `-`, `.`, `+`, `@`, 공백을
사용할 수 있습니다. `개인 드라이브`처럼 이름 중간의 공백도 허용하지만, `-`나 공백으로
시작하거나 공백으로 끝낼 수는 없습니다. 대소문자를 구분하며 앱의 별도 길이 제한은 없습니다.
내장 rclone의 검증에 따라 `remote-`처럼 이름 끝에만 하이픈을 한 개 붙인 이름도 거부됩니다.
Windows에서는 드라이브 문자와 혼동되는 영문 한 글자 이름을 피하세요.
Google Drive는 자체 OAuth client ID가 필요합니다. 인증은 시스템 브라우저에서 진행합니다.
**인증 페이지 다시 열기**는 진행 중인 인증 URL이 확인될 때만 표시됩니다. 인증 중 브라우저를
닫았거나 자동으로 열리지 않으면 이 버튼으로 로그인 페이지를 다시 열 수 있습니다.
인증 화면의 문구는 한국어로 표시하며, 실제 드라이브 이름, URL, 인증 명령과
서비스가 반환한 오류 상세는 원문을 보존합니다. 미등록 안내 문구는 원문으로 표시합니다.
질문은 rclone이 정한 기본값으로 시작하며, **고급 설정을 변경할까요?**의 기본 선택은
**아니요**입니다. 필수 항목(`*`)이 비어 있으면 다음으로 진행하지 않습니다. 직접 입력을 허용하는
선택 질문은 목록 외의 값도 입력할 수 있습니다.
**이전**으로 앞서 제출한 기본 설정 질문으로 돌아가 답변을 수정할 수 있습니다. 다시 **다음**을
누르면 바꾼 답변에 맞는 질문으로 진행합니다. OAuth나 OTP 등 인증 단계부터는 이전 이동을 지원하지
않으며, 앞의 설정을 바꾸려면 취소 후 다시 시작하세요. 설정은 단계마다 rclone config에 저장되므로
이전으로 돌아가거나 취소해도 이미 저장된 설정이나 진행한 인증을 되돌리지는 않습니다.
Google Drive, OneDrive, HiDrive, Google Photos는 계정을 추가하거나 재인증할 때 파일을 읽고 쓸
권한을 자동으로 요청하며, 해당 입력란은 표시하지 않습니다. Dropbox 등 요청 권한이
rclone에 내장된 서비스는 내장 설정을 사용합니다. 기존 연결의 권한이 부족하면 **재인증**에서
새 권한에 동의해야 합니다. Google Photos는 API 제약으로 rclone이 올린 사진과 동영상만
조회하거나 다운로드할 수 있습니다.
Koofr는 `provider`에 `koofr`, `user`에 계정 이메일, `password`에
[rclone용 앱 비밀번호](https://app.koofr.net/app/admin/preferences/password)를 입력하세요.
선택한 서비스에 해당하는 비밀번호 질문만 표시하며, 새로 입력한 원문은 앱이 rclone 저장 형식으로
변환합니다. 계정 추가와 재인증에 같은 처리를 사용합니다. 설정 완료 뒤 실제 연결 상태는 계정 관리의
용량 조회와 파일 목록에서 확인하세요.
파일 관리는 rclone 리모트의 최상위(`/`)를 기준으로 합니다. 앱에서 별도 관리
경로를 저장하거나 연결 시 폴더를 생성하지 않습니다. 범위를 제한하려면 rclone에서 해당
경로를 가리키는 리모트를 설정하세요.
계정이 두 개 미만이거나 적합한 대상이 부족하면 이중화 업로드를 시작하지 않습니다.

### 기존 config와 사용할 계정

기존 rclone config를 사용하려면 **설정 → 기존 rclone config**를 선택하고 재시작하세요.
원본 config를 복사하지 않으며, 토큰 갱신과 계정 추가는 선택한 파일에
반영될 수 있습니다. 암호화되지 않은 config만 지원합니다. 기존 암호화 config는 자동으로
변환하거나 덮어쓰지 않습니다. 암호화를 해제한 config를 사용하거나 새 `--data-dir`에서
계정을 다시 연결하세요.

**계정 관리**는 선택한 rclone config의 모든 리모트를 그대로 표시합니다. 앱은 별도 계정
목록을 저장하지 않고, **사용으로 변경**으로 활성화한 리모트 이름만 `settings.json`의
`enabled_remotes`에 저장하는 화이트리스트 방식을 사용합니다. config를 직접 편집해 추가한
리모트는 재시작 후 목록에 나타나며, 기본은 **사용 안 함**입니다. 사용할 리모트만 활성화하세요.
앱의 **계정 추가**에서 인증을 완료한 리모트는 바로 사용하며, 취소 후 config에 남은 리모트는
자동으로 활성화하지 않습니다. 사용하지 않는 리모트는 목록 조회, 업로드, 복제본 비교에서
제외합니다. 사용 여부를 바꿔도 config, 파일, 인증 정보는 그대로 유지됩니다. **기존 리모트 연결**과
**연결 해제**는 제공하지 않습니다.

**계정 삭제**는 확인 후 선택한 리모트 설정과 저장된 인증 정보를 rclone config에서 제거하고,
앱의 사용 목록에서도 이름을 지웁니다. 클라우드 파일과 서비스의 OAuth 승인은 유지됩니다.
같은 config를 쓰는 다른 프로그램과 이 리모트를 참조하는 설정에도 영향을 줍니다.
삭제에 앞서 사용 안 함 상태를 저장하므로 config 삭제가 실패하면 계정이 비활성 상태로 남을 수
있습니다. 사용 여부를 저장하지 못하면 config 삭제를 시작하지 않습니다. 마지막 계정을 삭제한
빈 config로도 앱을 다시 실행할 수 있습니다. 같은 이름을 다시 만들어도 사용은 자동으로 켜지지 않습니다.

사용 여부는 대소문자를 구분하는 리모트 이름을 기준으로 합니다. 같은 이름의 설정을 바꾸거나
외부에서 삭제 후 같은 이름으로 다시 만들면 저장된 사용 여부가 적용됩니다. config를 다른 파일로 바꾸면
사용 목록을 비우며, 재시작 전까지 계정 관리는 비활성화됩니다. 재시작 후 사용할 리모트를
다시 선택하세요. 외부 편집은 앱을 종료한 상태에서 하고 재시작해 반영하세요.

### 용량 표시와 갱신

계정 목록에서 전체 용량과 사용 가능 용량을 바로 확인할 수 있습니다. 창을 열면 사용 여부와
관계없이 각 리모트의 용량을 백그라운드에서 조회하며, 파일 목록은 읽지 않습니다. 지원하지 않는
제공업체는 **미지원**, 오류는 **조회 실패**, 반환되지 않은 용량은 `—`로 표시합니다. 조회 실패의
상세는 용량 칸의 툴팁에서 확인할 수 있습니다. 조회 중에도 사용 여부는 바꿀 수 있으며, 계정
추가, 재인증, 삭제는 조회가 끝난 뒤 가능합니다. 창을 닫으면 남은 용량 조회를 취소합니다.
사용 여부 버튼은 항목을 선택하면 활성화되고 현재 상태에 따라 **사용으로 변경** 또는
**사용 안 함으로 변경**으로 표시됩니다.

메인 창 상태표시줄은 `통합 용량(추정): 남은 110 GB / 전체 200 GB`처럼 각 값의 의미를
표시하며 용량 툴팁은 사용하지 않습니다. 사용 중인 쓰기 가능 계정에 서로 다른 두 사본을
저장할 수 있는 원본 파일 용량 기준입니다. 전체 용량은
`전체 합계의 절반`과 `가장 큰 계정을 제외한 용량 합계` 중 작은 값입니다. 예를 들어
1,000 GB 계정 하나와 100 GB 계정 두 개의 통합 전체 용량은 200 GB입니다.
남은 용량은 현재의 남은 용량 비율 우선 배치를 따라 계산하고 진행 중인 작업의 예약 공간도
뺍니다. 같은 계정들이 각각 100 GB씩 남았다면 작은 계정들을 먼저 사용하는 정책 때문에
남은 통합 용량은 약 110 GB입니다. 보고 있는 폴더나 화면 필터를 바꿔도 이 값은 같습니다.

작은 새 파일을 계속 업로드하는 경우의 추정치이며, 실제 파일 크기·순서·제공업체의 전송 공간·폴더별
제외·제공업체 파일 크기 제한에 따라 저장 가능량이 달라집니다. 파일별 업로드 공간 예약은
캐시의 추정 용량으로 확인합니다. 같은 저장 공간을 공유하는 여러 리모트는 자동으로 식별하지 않습니다.
용량 조회 미지원·실패·값 누락은 **확인 불가**로 표시하고, 쓰기 가능한 계정이 두 개 미만이면
`남은 0 B / 전체 0 B`로 표시합니다. 계정별 용량 조회 상태는 **계정 관리**에서 확인할 수 있습니다.
용량 조회 결과는 계정별로 메모리에 1시간 보관하고 저장 계정 추천·공간 예약·통합 용량 표시에서
공유합니다. 실제 조회 시각부터 1시간이 지나면 다음 추천 등에서 필요할 때 다시 조회하며,
주기적인 자동 조회는 하지 않습니다. 앱 시작·`F5` 새로고침·계정 관리 창 열기는 실제 용량을
조회해 캐시를 갱신합니다. 계정 관리 창 안에서는 조회 결과를 재사용합니다.
작업 중에도 **계정 관리**에서 계정 목록과 용량을 확인할 수 있습니다. **계정 추가**, **재인증**,
**사용 여부 변경**, **계정 삭제**는 진행 중인 작업과 결과 재확인이 끝나면 사용할 수 있습니다.
계정 관리 창 자체의 용량 조회가 진행 중이면 계정 추가·재인증·삭제는 그 조회가 끝날 때까지 기다립니다.
파일 목록 정렬은 계정 변경이나 설정 저장을 막지 않습니다.
전송 실행 직전과 작업 종료 후에는 용량 API를 다시 호출하지 않습니다. 성공 응답을 받은
업로드·복제·복사의 파일 크기를 대상 계정의 남은 용량에서 차감하고 해당 예약을 해제합니다.
일부 성공에서는 성공한 전송만 반영하며, 전송 후 검증 실패도 이미 성공한 전송의 사용량은 유지합니다.
덮어쓰기에서도 새 파일 전체 크기를 차감하고, 삭제·이동 원본 삭제로 반환될 공간은 휴지통·이전
버전의 영향을 단정할 수 없어 더하지 않습니다. 용량 보정은 캐시의 만료 시간을 연장하지 않습니다.
외부 변경·응답 유실·제공업체 반영 지연 때문에 추정값이 어긋나면 추천 대상에서 빠지거나 실제
전송이 용량 부족으로 실패할 수 있습니다. 이때 명시적으로 새로고침하세요. 용량 조회 실패와
미지원·값 누락도 같은 시간 동안 재사용하며, 명시적 새로고침은 다시 조회합니다.
폴더 이동·작업 진행 표시에서는 용량을 조회하지 않으며, 용량 갱신을 위해 파일 목록을 읽지 않습니다.

## 파일 탐색

- 파일 목록 아래 빈 공간이나 이름 열에서 파일명 뒤의 여백을 드래그하면 상자에 걸친 행을 선택합니다.
  `Ctrl`을 누른 채 시작하면 상자 안의 행을 기존 선택에 추가하거나 선택에서 뺍니다.
  목록의 위아래 가장자리까지 끌면 목록이 스크롤됩니다.
- 오른쪽 파일 목록과 왼쪽 **통합 클라우드** 트리 사이에서 파일이나 폴더를 드래그해 이동할 수
  있습니다. `Ctrl`을 누른 채 놓으면 복사합니다. 왼쪽 트리에서는 폴더를 끌 수 있고, 폴더나
  **통합 클라우드** 루트에 놓을 수 있습니다. **연결된 계정** 아래는 계정별 탐색에 사용합니다.
  내부 이동·복사는 각 복제본의 계정 안에서 경로를 바꾸며, 실행 전에 작업 범위를 확인합니다.
- Windows 탐색기에서 로컬 파일이나 폴더를 오른쪽 목록 또는 왼쪽 **통합 클라우드** 트리의
  폴더나 루트에 놓으면 그 경로에 업로드합니다.
- 오른쪽 목록의 파일을 Windows 파일 탐색기 폴더에 끌어 놓으면 다운로드할 수 있습니다.
  이름이 서로 다른 파일을 함께 놓을 수 있습니다. 폴더가 포함된 선택은 앱 안에서 드래그할 수 있습니다.
  여러 복제본 중 선택이 필요한 경우 앱에서 묻습니다.
  탐색기가 파일 내용을 처음 요청하면 선택한 파일을 모두 작업 목록에 각각 등록합니다.
  각 파일은 Windows 임시 폴더에 받은 뒤 탐색기에 넘깁니다.
  작업 목록에서 다운로드를 취소하면 탐색기에 해당 드롭의 복사 취소를 알립니다.
  임시 폴더가 있는 드라이브에도 여유 공간이 필요합니다. 같은 이름의 로컬 파일을 바꿀지는
  탐색기가 묻고, 클라우드 원본은 보존합니다.

파일 목록은 폴더를 먼저 표시하며, 기본으로 이름 오름차순 정렬합니다. 열 제목을 클릭하면
정렬 기준과 방향을 바꿀 수 있습니다.
파일 목록과 계정 관리, 문제 해결, 복제본 관리, 휴지통의 표는 긴 이름과 경로를 자동으로
줄바꿈하지 않습니다. 열 너비가 부족하면 끝에 말줄임표가 붙습니다. 열 제목 오른쪽 경계를
끌어 넓힐 수 있으며, 파일 목록에서는 항목에 마우스를 올려 전체 경로를 확인할 수 있습니다.

폴더를 이동하면 대상 폴더의 캐시를 먼저 표시합니다. 캐시가 없으면 첫 응답이 도착할 때까지
빈 목록과 조회 중 안내를 표시합니다.

폴더를 다시 조회할 때는 응답한 계정의 목록부터 갱신하며 **조회 중**으로 표시합니다. 응답을
기다리는 계정은 파일 작업 직후에도 캐시에 남은 목록을 화면의 상태 판정에 사용합니다. 조회 중에도
표시된 항목으로 작업을 요청할 수 있으며, 작업은 별도로 최신 상태를 확인합니다. 조회에 실패한
계정은 이전 목록을 표시하되 이번 조회에서 확인된 복제본 수에는 포함하지 않습니다.
다운로드 완료만으로는 클라우드 목록을 새로고침하지 않습니다. 변경 경로를 알 수 있으면 해당
폴더와 영향받을 수 있는 상·하위 목록만 만료시킵니다. 변경 경로를 알 수 없거나 사용 중인 리모트가
별칭처럼 다른 경로에서 같은 저장소를 보여줄 수 있으면 전체 목록을 만료시킵니다. 여러 작업이 끝나면
탐색 화면 갱신과 문제 재확인에 필요한 같은 폴더의 목록을 한 번 조회하고, 문제 목록도 한 번
갱신합니다. 조회 중에 끝난 작업은 다음 조회에서 확인합니다.

파일을 더블클릭하면 **설정 → 기본 다운로드 폴더**에 원래 이름으로 받습니다. 해당 폴더가
없으면 만들고, 같은 이름의 파일이 있으면 덮어쓸지 묻습니다. **다운로드...** 버튼을 누르면 저장 위치를 고르는 창이 열립니다.

통합 보기에서 상태가 **정상**인 파일은 복제본이 있는 계정 중 대기·진행 중인 다운로드가 가장
적은 계정에서 받습니다. 건수가 같으면 후보 계정을 순서대로 번갈아 사용합니다. 계정별 보기와
복제본 관리에서는 선택한 계정의 복제본을 받습니다. **진행 내용**과 **작업 결과**의 전송·검증
단계에는 다운로드 원본의 클라우드 계정과 경로를 표시합니다.

주소창이나 탐색 버튼으로 이동하거나 오른쪽 목록에서 폴더를 열면 왼쪽 트리도 현재 경로까지
자동으로 펼쳐 선택합니다. 경로를 확인한 폴더는 오른쪽 목록을 조회 중이어도 바로 선택합니다.
아직 상위 경로를 확인하지 못했다면 해당 목록이 도착하는 대로 선택합니다. 통합 보기와 계정별
보기에 각각 적용됩니다.

## 파일 작업

- 작업 확인창에 전체 작업 내용을 표시합니다. 내용이 길면 본문 안에서 스크롤하며 확인·취소
  버튼은 아래에 고정됩니다.
- **새 폴더...**에서 이름을 입력하고 확인하면 별도 확인창 없이 작업 큐에 등록합니다.
  재시도도 같은 경로를 다시 확인한 뒤 바로 등록합니다.
- 파일·폴더 업로드는 준비가 끝나면 바로 등록합니다. 대상 계정에 같은 경로의 파일이 있는 경우에만
  해당 경로와 계정을 표시하고 **덮어쓰기** 또는 **건너뛰기**를 묻습니다. **남은 모든 항목에 적용**을
  체크하면 아직 결정하지 않은 항목의 계정과 경로를 함께 표시합니다. 이어서 누른 버튼의 선택을
  표시된 항목 전체에 적용합니다. 창을 닫으면 현재 항목만 건너뜁니다. 건너뛴 파일은 모든 대상에서
  제외되고 새 파일은 계속 등록됩니다. 같은 대상 경로로 올릴 항목이 여러 개면 등록 전에 중단합니다.
  파일 작업을 재시도하면 그 파일의 최신 상태를 조회하고 기존 파일이 있는 경우 다시 묻습니다.

**복제본 관리**는 선택한 모든 항목을 한 창에 엽니다. 상단의 항목 목록을 전환하며 확인하고,
각 항목에서 원본 복제본과 작업을 직접 선택하세요. 작업을 요청해도 창을 유지하므로 다른 항목을
계속 확인할 수 있습니다. 복제본 관리 창의 목록은 연 시점의 결과입니다. 변경 작업이나 정밀 검증이
끝나면 문제 해결 목록에서도 해당 경로를 다시 확인해 해결된 항목만 제거합니다.

복제본 관리에서는 한 파일의 정밀 검증을 요청하면 복제본마다 작업 행을 표시합니다. 모든 읽기가
완료되고 원본 상태를 다시 확인한 뒤 비교 결과를 표시하고 저장합니다. 전송량 확인 전부터 결과 확인과
문제 목록 재확인까지 검증 경로와 겹치는 작업을 막습니다. 그동안 다른 경로의 항목을 선택해
다운로드·복제·삭제할 수 있습니다. **다운로드...**와 **복제...**도 요청을 시작한 시점부터 작업과 결과 재확인이
끝날 때까지 반복 요청을 막습니다. 항목을 바꾸거나 창을 다시 열어도 진행 중인 요청의 잠금은 유지됩니다.
**복제...**에서 다른 계정을 선택하고 기존 파일 교체를 승인하면 충돌한 파일의 버전을 맞출 수 있습니다.

파일 목록과 복제본 관리에서 **삭제...**를 누르면 선택한 계정과 경로를 표시한 확인창이 바로 열립니다.
파일 목록은 현재 계정 필터에 해당하는 복제본을, 복제본 관리는 선택한 복제본 하나를 대상으로 합니다.
파일 목록에서 여러 항목을 선택하면 겹치지 않는 경로마다 작업 행이 생깁니다. 선택한 폴더와 하위 항목은
함께 조회하고 중복을 제거한 뒤 파일부터 삭제합니다. 승인한 대상이 바뀌었거나 조회에 실패하면 해당
작업이 중단됩니다. 재시도할 때도 그 작업의 계정과 경로를 다시 확인합니다.

**진행 내용**에는 대상 확인, 하위 항목 조회, 파일 삭제, 빈 폴더 삭제 단계의 계정과 경로를 표시합니다.
하위 조회가 끝나면 `파일 삭제 · 3/10`처럼 전체 삭제 대상 중 현재 순서를 표시합니다. 중단 시에는
완료 건수와 중단 위치를 남깁니다. 기존 검사 결과를 다시 확인할 때는 삭제 결과와 함께 조회 중인
상위 폴더와 응답을 기다리는 계정을 표시합니다. 삭제와 필요한 재확인이 끝날 때까지 해당 경로 및
상·하위 경로의 변경을 막으며, 복제본 관리에서는 삭제 실행이 끝나면 다른 경로의 작업 버튼을 다시 사용할 수 있습니다.

일반 파일 작업도 계획을 만드는 동안 반복 제출을 막고, 대기·실행·재확인 중인 작업의
원본·대상 또는 상·하위 경로와 겹치는 변경 계획은 추가 등록하지 않습니다. 로컬 다운로드
대상의 중복도 확인하며, 다른 경로의 작업은 계속 등록할 수 있습니다. 같은 폴더의 새로고침·
폴더 검사·계정별 휴지통 조회·같은 휴지통 항목 복원도 진행 중 반복 요청을
막습니다. 계정 관리의 변경 버튼은 계정 작업 중 비활성화하며, 인증 취소 요청도 한 번만 보냅니다.

### 업로드와 이동의 실행 범위

- 모든 변경은 최신 정보로 범위를 만듭니다. 복제·복사·이동·이름 변경·삭제는 범위를 확인받은 뒤 실행합니다.
- 파일을 더블클릭하거나 **다운로드...**에서 저장 위치를 선택하거나 파일 탐색기에 파일을 놓으면
  다운로드를 시작합니다. 기존 파일을 덮어쓸 때만 확인하며, 앱의 다운로드 재시도에도 같은 기준을 적용합니다.
- 업로드·다운로드·복제는 rclone의 기본 파일 전송으로 최종 경로에 직접 저장합니다. 승인한
  기존 대상도 같은 방식으로 덮어씁니다.
  첫 변경 전에 계획의 복사 원본과 기본 대상을 확인합니다. 먼저 만들 폴더가 없으면 첫 원본과
  첫 대상은 첫 전송 직전에 확인하고, 나머지 원본과 기본 대상은 그 전에 확인합니다. 대체 대상은
  사용하기 직전에 다시 조회합니다. 전송마다 직전 상태와 전송 결과를 확인합니다.
  업로드 준비 중에는 상태표시줄에 확인 중인 파일·폴더와 응답을 기다리는 계정이 표시됩니다.
  **준비 취소**를 누르면 진행 중인 조회를 정리하고 작업 등록 전에 업로드 준비를 끝냅니다.
  준비 중에는 계정별 대상 조회를 최대 4개씩 병렬로 진행하고, 같은 준비 작업에서 확인한 폴더의
  존재 여부와 목록, 계정 기능을 재사용합니다. 각 파일은 두 대상의 공간을 확보한 뒤 전송합니다.
  새 파일의 기본 대상에 공간을 예약할 수 없으면 준비 때 정한 대체 후보의 공간을 순서대로 확인합니다.
  기존 대상과 선택한 대체 대상의 경로가 여전히 비어 있는지 확인하고, 두 대상의 공간을 확보하지
  못하거나 경로 상태가 달라졌으면 해당 파일을 쓰기 전에 중단합니다.
  전송 단계에서도 새 파일이 쓰기 전에 거부됐음이 확인되면 남은 대체 후보를 순서대로 시도합니다.
  현재 Box의 파일 크기 제한 사전 거부를 이 조건으로 처리합니다. 대체 후보가 있는 새 Box
  전송의 rclone 복사 시도는 한 번으로 제한합니다. 기존 파일 교체에서 거부되면 해당 파일의
  전송을 중단합니다. 응답 유실 등 결과가 불명확하면 원래 대상의 내용을 확인하고, 일치가 확인된
  사본은 성공으로 계산합니다. 확인이 불가능하면 작업을 중단합니다.
  작업 목록의 진행 내용과 작업 결과에서 공간 부족이나 전송 거부 이유, 대체 계정, 전송 결과 확인 상태를 볼 수 있습니다.
  임시 업로드 여부·교체 방식과 실패 시 기존 파일 보존 여부는 rclone과 제공업체의 동작을
  따릅니다. 모든 클라우드에서 원자적 교체나 이전 버전 복구를 보장하지 않습니다.
- 여러 파일을 이동하면 모든 대상 복사·검증 작업이 완료된 뒤 **이동 · 원본 삭제**가 시작됩니다.
  전송이 실패하거나 원본 삭제 전 재확인에서 대상 변경·부재 또는 조회 실패가 발견되면 원본과
  이미 만든 사본을 보존합니다. 파일 작업을 재시도하면 그 파일의 범위를 다시 확인합니다.
  폴더 생성과 원본 삭제는 해당 요청의 선행 작업 결과에 따릅니다.
- 일괄 복사·이동의 준비에서는 원본을 고를 때 읽은 목록을 이름 충돌 검사에도 사용합니다.
  폴더 삭제에서는 파일의 이름 충돌 검사에 목록을 공유하고, 각 폴더는 하위 항목을 읽기 직전에
  새 목록으로 확인합니다. 파일별 상태를 확인하고 실제 전송과 파일 삭제 직전에 다시 조회합니다.
- 파일·폴더의 대소문자만 바꾸는 경우 각 리모트에서 rclone의 이름 변경을 실행하고, 실제 목록에서
  최종 이름을 확인합니다. 제공업체에 따라 rclone이 내부 이동에 임시 이름이나 복사를 사용할 수
  있으며, 작업이 중단되면 일부 계정에 이전 이름이나 rclone의 중간 항목이 남을 수 있습니다.
- 삭제는 rclone이 처리합니다. 휴지통 이동 여부는 제공업체와 리모트 설정에 따르며, 삭제 후 복구하지 못할 수 있습니다.
  앱에서 휴지통을 비우거나 영구 삭제 방식을 별도로 선택하는 기능은 제공하지 않습니다.
- 백엔드에서 빈 폴더를 저장하지 못하면 가상 디렉터리 제한을 표시합니다.
- 외부 프로그램의 동시 변경과 제공업체의 일관성 지연까지 원자적으로 막을 수는 없습니다.
  불일치가 보이면 중단하며, 실제 사용자 자료에 쓰기 전 테스트 계정으로 검증해야 합니다.
- 충돌·검증 불가 파일은 개별 복제본을 선택하여 다운로드하세요. 폴더 일괄 다운로드는 제공하지 않습니다.
- 일부 Windows 금지 이름의 원격 객체는 앱 내 변경·다운로드가 제한될 수 있습니다.
  자동 이름 변경 대신 해당 제공업체에서 확인하세요.

### 작업 큐와 재시도

**작업** 패널에서 진행 중인 행이 보이면 다음 진행 항목으로 스크롤이 따라갑니다. 진행 행을
화면 밖으로 스크롤하면 현재 위치를 유지하며, 진행 행을 다시 보이게 하면 추적이 재개됩니다.
취소 요청과 결과 재확인도 진행에 포함하며, 선택한 행과 가로 스크롤 위치는 유지합니다.

조회나 작업 중에도 **설정**에서 기본 다운로드 폴더, 목록 캐시 만료 시간, 앱 로그 수준과
네트워크 재시도 수를 저장할 수 있습니다. 재시도 수는 저장 후 작업 큐에 등록하는 작업에 적용됩니다.
동시 전송 수나 rclone config를 바꿨다면 작업과 결과 재확인이 끝난 뒤 저장할 수 있습니다.
설정을 저장해도 작업 기록은 유지됩니다.

**설정 → 동시 전송 수**는 동시에 실행할 파일 전송 작업 수를 정합니다. 업로드, 다운로드,
복제, 내부 복사와 이동의 전송 단계에 적용됩니다. 기본값은 2이며 1~8로 설정할 수 있습니다.
업로드·내부 복사·이동의 파일은 각각 작업 행에 표시됩니다. 한 파일의 여러 계정 전송은 같은 행에서
순서대로 실행합니다. 새 폴더는 경로별 작업으로 등록하고, 파일과 하위 폴더는 필요한 상위 폴더가
생성된 뒤 시작합니다. 폴더 생성이 실패하면 하위 작업은 쓰기 없이 실패로 표시되고 다른 경로는 계속 처리합니다.
파일 업로드 재시도는 해당 파일과 필요한 상위 폴더를 다시 확인합니다.
폴더 검사는 전용 큐에서 최대 두 폴더를 병렬로 조회하므로 전송 한도가 찬 상태에서도 시작할 수 있습니다.
삭제, 폴더 생성, 휴지통 복원, 정밀 검증은 전송과 별도인 큐에서 합계 최대 두 건씩 실행됩니다.
모든 큐의 진행과 취소는 같은 **작업** 패널에서 확인할 수 있습니다.

**작업** 패널과 문제 해결 창에는 계획 조회부터 현재 단계, 계정, 전체 경로와 단계별 처리 순번 및 전체
건수를 표시합니다. 실행 중에는 폴더 생성, 전송, 전송 검증을 구분하고,
결과 재확인 중에는 조회 중인 상위 폴더와 아직 응답을 기다리는 계정을 표시합니다.
작업 패널의 **진행 내용** 칸에서 전체 내용이 잘리면 마우스를 올려 확인할 수 있습니다.
작업 행을 우클릭하면 **작업 취소**, **최신 상태로 재시도...**, **작업 결과**, **이 작업 지우기**를
상태에 따라 사용할 수 있습니다. 행을 선택하고 `Shift+F10`을 눌러도 같은 메뉴가 열립니다.
**완료한 작업 지우기**는 **완료** 기록을, **실패한 작업 지우기**는 **실패**, **실패 / 결과 확인 필요**,
**일부 성공** 기록을 한꺼번에 지웁니다. **취소됨** 기록은 행 메뉴의 **이 작업 지우기**로 지울 수 있습니다.
모든 지우기 명령은 결과 재확인까지 끝난 작업의 결과와 재시도 항목을 목록에서 지웁니다.

## 폴더 검사와 문제 해결

**현재 폴더 검사**는 사용 중인 계정에서 현재 경로와 그 하위 폴더를 조회합니다. 루트(`/`)에서
실행하면 전체 관리 범위를 검사합니다. 화면 필터와 관계없이 해당 경로의
복제본을 비교하며, 파일 내용을 다운로드하거나 변경하지 않습니다. 발견한 폴더마다 작업 행이 생기고,
검사 결과는 시작 경로 기준으로 합쳐집니다. 폴더 작업을 취소하면 그 경로 아래는 검사하지 않으며
결과에 미완료로 표시합니다. 왼쪽 **문제 항목**에서 최근 검사 결과와 검사한 경로를 확인할 수 있습니다.

검사가 끝나고 문제가 있으면 **문제 해결** 창이 열립니다. **관리 → 문제 해결**에서 최근
결과를 다시 열 수도 있습니다. `Ctrl`이나 `Shift`로 여러 행을 선택하거나 `Ctrl+A` 또는 **전체 선택**으로
목록 전체를 선택할 수 있습니다. **선택 해제**로 선택을 비웁니다. 상단에는 선택한 항목의
폴더 생성, 복제, 정밀 검증, 개별 확인 건수를 표시하며, 정밀 검증을 선택하면 예상 읽기 용량도
표시합니다. 크기를 모르는 복제본이 있으면 읽기 용량 미확인으로 표시합니다.

| 상태 | 해결 방법 |
| --- | --- |
| 디렉터리 불일치 | **선택 문제 해결**로 사용 중인 쓰기 가능 계정 중 빈 폴더를 지원하는 계정에 누락된 폴더만 생성합니다. 폴더 안의 파일은 복제하지 않습니다. |
| 복제 부족 | **선택 문제 해결**로 파일마다 대상 계정을 자동 선택하고 사본 하나를 추가합니다. 복제 후 비교 가능한 해시가 부족하면 같은 작업에서 정밀 검증까지 이어집니다. |
| 충돌 또는 복제 초과 | **복제본 관리**에서 남길 버전을 직접 선택해 복제하거나 불필요한 사본을 삭제합니다. |
| 검증 불가 | **선택 문제 해결**로 각 복제본의 실제 바이트를 읽어 SHA-256으로 정밀 검증합니다. 재사용 근거가 있는 결과는 저장해 다음 검사에도 적용합니다. |
| 확인 불가 | 연결, 인증, 권한 문제를 먼저 해결하고 다시 검사하세요. **복제본 관리**에서 개별 복제본을 확인할 수 있습니다. |

`비교 가능한 해시 부족`은 제공된 해시만으로 복제본의 내용 일치를 판단할 수 없다는 뜻입니다.
**선택 문제 해결**로 정밀 검증하면 파일을 변경하지 않고 내용을 비교합니다. 검증 후 최신 상태를
다시 조회해 정상인 항목만 목록에서 제거하고, 내용이 다르면 `충돌`로 남깁니다. 검증 결과의
영구 재사용 근거가 없거나 DB 저장에 실패해도 이번에 직접 읽은 결과는 마지막 재확인에 사용합니다.
모든 계정의 조회가 성공하고 읽은 복제본의 원격 정보가 그대로이며 내용이 일치하면 이번 문제는
해결됩니다. 이후 탐색하거나 다시 검사하면 `검증 불가`가 될 수 있습니다.
개별 검증은 **복제본 관리 → 정밀 검증...**에서도 실행할 수 있습니다.

**선택 문제 해결**을 누르면 디렉터리 불일치, 복제 부족, 검증 불가 항목을 별도 확인창 없이
항목별 작업으로 바로 등록합니다. 대량 선택은 작은 묶음으로 나누어 등록하므로 등록 중에도
화면을 조작할 수 있으며, 앱을 종료하면 추가 등록을 중단합니다. 정밀 검증도 이 클릭으로
실제 바이트 읽기를 시작하므로 선택 요약의 읽기 용량을 확인하세요. 검증 결과와 저장 건수는
해당 작업의 **작업 결과**에 표시합니다.
복제 보충 뒤에도 해시 비교가 불가능하면 별도 확인창이나 새 작업 없이 현재 복제본의 실제 바이트를
읽습니다. 보통 파일 크기의 두 배만큼 추가 읽기가 발생할 수 있으며,
불일치는 충돌로 남깁니다. 복제는 성공하고 정밀 검증만 실패하면 일부 성공으로 표시하고,
재시도할 때 현재 두 사본이 있으면 복제를 반복하지 않고 검증부터 진행합니다.
각 작업은 실행 차례에 최신 상태와 복제 대상을 조회하고 용량은 공유 캐시의 추정값으로 확인합니다. 준비가
끝나면 실행하므로 전체 선택의 계획이 끝날 때까지 기다리지 않습니다. 항목별 조회 시간은 여전히
필요합니다. 작업 이름에 전체 논리 경로를 표시하며, 해당 행의 우클릭 메뉴에서 **작업 취소**를
선택하면 그 작업만 중단합니다. 이미 반영한 변경은 되돌리지 않습니다.
같은 폴더의 여러 계정에 대한 생성은 한 작업으로 묶습니다. 하위 작업은 필요한 상위 폴더 생성이
완료된 뒤 실행하며, 선행 폴더 작업이 실패·취소되면 관련 하위 작업은 실행하지 않고 실패로 표시합니다.
관련 없는 항목은 계속 처리합니다. 충돌이나 복제 초과처럼 개별 확인이 필요한 항목은 제외합니다.
등록 준비부터 모든 작업과 필요한 결과 재확인이 끝날 때까지 버튼을 비활성화해
중복 제출을 막습니다. 문제 해결 작업의 **최신 상태로 재시도...**는 해당 항목만 다시 등록하고
별도 확인창 없이 최신 상태를 조회한 뒤 실행합니다.

작업이 완료되거나 일부 성공하면 처리한 경로를 모든 사용 계정에서 다시 조회합니다. 정상 또는 모든
계정에서 없어졌음이 확인된 항목만 문제 해결 목록과 메인 창의 문제 항목에서 제거합니다.
문제가 남으면 최신 상태로 표시하며, 확인할 수 없는 항목은 유지합니다. 선택하지 않은 항목은
이 재확인으로 변경하지 않습니다. 등록한 작업들이 모두 종료되고 필요한 재확인까지 끝난 뒤
다시 사용할 수 있습니다. 상태 변경·조회·용량 확인 문제는 해당 작업의 실패로 표시하며
**작업 결과**에서 원인을 확인할 수 있습니다. 관계없는 항목은 계속 진행하므로 일부 항목이
실패해도 다른 항목은 이미 반영되었을 수 있습니다. 실패한 항목은 문제 목록에 남습니다.
등록 도중 오류가 나면 이미 등록한 작업은 계속 추적하며, 등록하지 못한 항목은 문제 목록에 남습니다.

복제 계정은 같은 경로의 파일이 없는 계정 중에서 선택합니다. 전송할 파일 크기와 진행 중인
작업의 예약 용량, 파일 크기 제한을 확인하며, 복제 후 남는 용량 비율이 높은 계정을 우선합니다.
대상마다 새 파일 한 개 크기의 공간을 예약하며, 제공업체가 요구하는 추가 전송 공간에 따라 실패할 수 있습니다.
문제 해결은 항목별 계획과 공간 예약을 순서대로 처리해 다음 항목의 추천에 활성 작업의 예약
용량을 반영합니다. 전송은 계획 잠금을 해제한 뒤 수행하며, 대기 항목 전체의 공간을 미리 예약하지 않습니다.
비율을 알 수 없으면 남는 용량을 비교하고, 용량을 알 수 없는 계정은 후순위로 둡니다.
미사용·읽기 전용·제공업체 제외 경로는 대상에서 뺍니다. 용량 조회에 실패한 계정도 선택하지 않습니다.

폴더 생성·복제는 실행 전에 해당 경로를 다시 조회합니다. 조회에 실패하거나 문제 상태가 달라졌으면
중단하며, 복제 부족 해결에서는 기존 파일을 교체하지 않습니다. 진행 상황과 실패는 작업 큐에서
확인하세요. 전체 범위를 갱신하려면 문제 해결 창의 **다시 검사...**를 사용합니다.
탐색 중인 폴더를 바꿔도 이 재검사 범위는 바뀌지 않습니다.

## 제공업체별 제외 경로

제외 규칙은 프로그램에 내장되어 있으며 설정 파일이나 화면에서 변경하지 않습니다.
현재 적용하는 규칙은 다음과 같습니다.

| rclone 제공업체 | 제외 경로 |
| --- | --- |
| PikPak (`pikpak`) | 리모트 최상위 `/My Pack`과 그 안의 모든 항목 |
| 그 외 | 내장 제외 경로 없음 |

제외 경로는 통합·계정별 탐색, 폴더 트리, 검사·비교, 업로드·복제 대상, 다운로드·이동·삭제·
정밀 검증에 같은 기준으로 적용합니다. 주소를 직접 입력해도 해당 리모트의 제외 경로를 조회하지
않으며, 작업 실행 전에도 원본·대상의 제외 여부를 다시 확인합니다. 실제 폴더와 파일은
삭제하거나 변경하지 않습니다. 계정 용량은 제공업체 전체 보고값이므로 제외된 파일의 사용량도
포함할 수 있습니다.

경로 비교는 앱의 다른 경로와 같이 Unicode 정규화와 대소문자 구분 없이 수행합니다.
`My Pack 2`나 `other/My Pack`, 다른 제공업체의 같은 이름 폴더는 제외하지 않습니다.
같은 경로가 다른 제공업체에 있으면 그 리모트에서는 사용할 수 있고, 제외한 계정 때문에
디렉터리 불일치로 판정하지 않습니다. 업로드는 제외 경로를 쓰지 않는 서로 다른 계정 두 개가
확보되어야 시작합니다.

이 규칙은 rclone에 등록된 제공업체와 리모트 경로를 기준으로 합니다. `alias`·`crypt`나
`root_folder_id` 등으로 변경한 경로의 원래 클라우드 위치까지 추적하지 않습니다. 제공업체가
기본 폴더의 이름이나 위치를 바꾸면 프로그램의 규칙 갱신이 필요합니다.

## 정밀 검증과 캐시

- QuickXor/CRC 자체를 내용 일치의 근거로 사용하지 않습니다. 해시가 없는 파일의 객체 ID 또는
  경로와 크기·수정 시각을 통한 캐시 재사용에는 아래의 변경 감지 한계가 있습니다.
- Drive와 OneDrive는 비교 가능한 해시가 없어 `검증 불가`가 될 수 있습니다.
  정밀 검증은 실제 바이트를 읽으므로 문제 해결의 예상 읽기 용량이나 개별 검증의 전송량 안내를
  확인하고 실행하세요.
- 정밀 검증은 **제공업체·해시 종류·제공업체 해시값 → 실제 바이트의 SHA-256**을
  `content_hashes.db`에 저장합니다. 이후 탐색·검사·재시작에서 같은 키가 확인되면 파일을 다시
  다운로드하지 않고 SHA-256을 재사용합니다. 내용 해시 키는 같은 제공업체라면 계정·경로·config가 달라도
  재사용하며, 해시 종류가 다른 복제본도 각 키에서 찾은 SHA-256으로 비교합니다. 내용이 다르면
  충돌로 표시합니다. 문제 해결 대기 중 다른 파일의 검증으로 캐시가 채워진 경우에도 재사용합니다.
- 저장 대상은 MD5·SHA-1·SHA-256·Dropbox·BLAKE3·Whirlpool의 유효한 해시값입니다. 내용 해시
  키에는 계정·경로·크기·수정 시각·객체 ID·콘텐츠 버전을 포함하지 않습니다. 동일 키에서 서로 다른 SHA-256이
  발견되면 그 키는 재사용을 중단하고, 나중에 다시 검증해도 자동으로 재활성화하지 않습니다.
  여러 저장 해시의 결과가 모순되는 파일도 캐시로 검증 완료 처리하지 않습니다.
- 해시를 전혀 받지 못한 파일에 객체 ID와 신뢰할 수 있는 콘텐츠 버전이 모두 있으면 같은 테이블에
  해시 종류 `object-version`으로 저장합니다. 해시값 칸에는 계정·리모트 루트·객체 ID·콘텐츠
  버전의 JSON 배열을 넣습니다. 연결 설정의 해시는 계산하거나 저장하지 않으므로 토큰 갱신이나
  다른 리모트 설정 변경으로 재사용이 중단되지 않습니다. 계정은 리모트 이름으로 구분하므로,
  같은 이름을 다른 실제 계정으로 바꾸면 일치하는 식별 정보에 과거 캐시가 적용될 수 있습니다.
- 해시와 콘텐츠 버전이 모두 없으면 해시 종류 `object-metadata`를 사용하고, 같은 계정·리모트
  루트·객체 ID에 파일 크기·수정 시각을 결합해 정밀 검증의 SHA-256을 재사용합니다.
  객체 ID가 없으면 아래의 경로 기반 키를 사용합니다. 크기·수정 시각이 없으면 저장하지 않습니다.
  수정 시각은 앱에서 읽은 값을
  UTC·마이크로초 단위로 통일합니다. 이 방식은 메타데이터상 변경이 없다는 추정입니다.
  **같은 크기로 내용을 변경하고 수정 시각을 유지하거나, 제공업체의 시각 정밀도 때문에 변경이
  구분되지 않으면 과거 SHA-256을 적용해 정상으로 판단할 수 있습니다.**
- 해시와 객체 ID가 모두 없으면 `path-metadata` 키를 사용합니다. 같은 계정·리모트
  루트에 파일의 정확한 상대 경로·크기·수정 시각을 결합합니다. 경로의 대소문자와 이름을 그대로
  구분하므로 이동·이름 변경 후에는 다시 검증합니다. **파일을 삭제한 뒤 같은 경로에 크기·수정
  시각이 같은 다른 파일을 넣으면 과거 SHA-256을 잘못 적용할 수 있습니다.** 기존 네 필드와
  기본키는 유지하며 DB 변환은 하지 않습니다. 새 키는 이후 정밀 검증 때부터 저장됩니다.
- 설정 범위가 포함된 과거 객체·경로 키는 읽어 재사용하거나 변환하지 않습니다. 기존 DB와 행은
  그대로 두며, 필요한 파일을 다시 정밀 검증하면 현재 키로 저장합니다. 내용 해시 키는 그대로 사용합니다.
- 현재 내장 rclone의 공통 목록·상세 조회에는 신뢰할 수 있는 콘텐츠 버전이 노출되지 않습니다.
  사용자가 편집할 수 있는 메타데이터의 `version`도 사용하지 않으므로, 해시가 없는 실제 리모트는
  객체 ID·크기·수정 시각이 있으면 `object-metadata`, ID 대신 경로를 사용하면 `path-metadata`로
  저장합니다. QuickXor·CRC만 있는 파일과 유효한 식별 정보·크기·수정 시각이 부족한 파일은 영구
  저장 대상에서 제외합니다. 이런 파일은 이번 정밀 검증과
  직후 문제 재확인에만 실제 읽은 SHA-256을 적용하며, 이후 새 탐색·검사에서는 다시 읽어야 할 수 있습니다.
- 정밀 검증 도중 변경·취소·조회 실패가 있으면 그 검증 결과를 저장하지 않습니다. DB를 읽거나
  쓸 수 없으면 파일 원본과 DB를 보존하고 저장 결과 없이 검사합니다. 정밀 검증 결과 창에서
  다음 조회에 재사용할 결과의 저장 건수와 저장 실패를 확인할 수 있습니다.

`content_hashes.db`에는 검증한 파일의 바이트나 인증 토큰을 저장하지 않습니다. 경로 기반 키에는
상대 경로가 포함됩니다. 앱을 종료한 뒤 이 DB를 삭제하면 저장 결과가
사라져 다시 정밀 검증해야 하며, 클라우드 파일에는 영향을 주지 않습니다. 포터블 이동 시
이 DB도 함께 복사하면 검증 결과를 유지할 수 있습니다. 기존 `verification.sqlite3`는 읽거나
변환하지 않으며 자동으로 삭제하지도 않습니다. 이전 검증 결과는 새 DB에 다시 쌓아야 합니다.

## 데이터 폴더와 로그

배포본의 기본 데이터 폴더는 **`CloudCluster.exe`와 같은 폴더**입니다.

앱 설정에서 알 수 없는 키는 버리고 잘못된 값은 기본값으로 교체해 파일을 정리합니다.
사용 리모트 목록은 유효한 이름만 남기고 중복을 제거합니다. JSON 자체가 손상됐으면 전체
기본값으로 시작하며 모든 리모트는 사용 안 함이 됩니다. 파일을 읽거나 정리한 내용을 저장할
수 없어도 앱은 계속 실행합니다. 읽지 못한 파일과 저장에 실패한 원본은 유지합니다.
외부 config 경로가 없거나 유효하지 않으면 기본 `rclone.conf`로 돌아가고 사용 목록을 비웁니다.
이 정리는 앱 JSON에만 적용하며, 클라우드 인증 정보가 있는 rclone config는 변경하지 않습니다.
소스 실행의 기본 위치는 프로젝트 루트입니다.
쓰기 가능한 앱 전용 폴더에서 실행하세요. `--data-dir "D:\CloudClusterData"`로 위치를 바꿀 수 있습니다.
기존 AppData 설정은 자동으로 읽거나 이동하지 않습니다. 기존 위치를 `--data-dir`로 지정하거나,
앱을 종료한 뒤 설정 폴더의 파일을 새 위치로 복사하세요.

앱 JSON에는 토큰을 저장하지 않습니다. `rclone.conf`에는 클라우드의 접근·갱신 토큰과
제공업체별 접속 정보가 **암호화 없이 저장**됩니다. 이 파일을 읽을 수 있는 사람은 저장된 토큰을
사용할 수 있으므로 공개하거나 공유하지 마세요. 앱은 저장한 폴더의 기본 파일 권한을 따릅니다.
DPAPI와 config 암호를 사용하지 않으며 `config-key.dpapi`나 외부 config용 보호 키를 생성하지
않습니다. 이전 버전의 암호화 config는 거부하며 기존 보호 키는 사용하거나 삭제하지 않습니다.
exe·`settings.json`·평문 `rclone.conf`를 함께 옮겨 다른 Windows PC에서 사용할 수 있습니다.
이동 후에는 다운로드 폴더와 외부 config의 절대 경로를 새 PC에 맞게 확인하세요.
클라우드 제공업체가 인증을 취소하거나 추가 인증을 요구하면 다시 연결해야 합니다.
손상되었거나 암호화된 config는 빈 설정으로 덮어쓰지 않습니다.
동일 설정 폴더의 단일 인스턴스만 실행합니다. 작업 큐 영구 저장·영구 작업 저널·마운트는 사용하지 않습니다.

### 로그

**설정 → 앱 로그 수준**에서 아래 수준을 선택할 수 있습니다. 자세한 수준에는 그보다 높은 수준의
기록도 포함됩니다.

| 수준 | 기록 내용 |
| --- | --- |
| **ERROR** | 시작 실패와 최종 작업 실패·일부 성공. 작업 ID, 실패 단계와 오류 종류, 확인된 제공업체 오류 정보와 전송 결과를 남깁니다. |
| **WARNING** | 원격 호출 실패, 일부 계정 조회 실패, 결과 재확인 실패, 검증 캐시 사용 불가 등 확인이 필요한 상황을 추가합니다. |
| **INFO** (기본값) | 작업 등록·시작·종료, 대기·실행 시간, 단계별 성공·실패 건수와 결과 재확인을 추가합니다. |
| **DEBUG** | 단계와 원격 호출의 시작·완료 및 소요 시간, rclone 파일 작업의 오류 메시지를 추가합니다. |

오류 종류와 전송 결과는 따로 기록합니다. 권한 오류 뒤에 `write_result=unconfirmed`가 있으면 대상에
파일이 생겼는지 확인하세요. 로그는 파일당 2 MiB에서 교체하며 이전 로그를 최대 3개 보관합니다.
재현 직후 최신 로그와 필요하면 이전 로그 `cloud-cluster.log.1`도 확인하세요.

일반 로그에서 경로와 계정은 같은 앱 실행 안에서 비교할 수 있는 임시 식별자로 표시합니다. DEBUG에서는
파일 작업의 오류 메시지에 들어 있는 경로와 계정명이 보일 수 있습니다. URL과 인식 가능한 토큰·비밀번호
형태는 가리고, 긴 메시지는 4,096자로 제한합니다. 인증·설정 오류 메시지와 RC 요청·응답 전체는 저장
대상에서 제외합니다. 공유 전에 로그 내용을 확인하세요.
